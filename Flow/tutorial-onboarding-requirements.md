## 1. 目的（方針の核心）

本チュートリアルは **機能一覧の説明ではない**。

ユーザーが手順をこなすことで、**実際のシーン上にミニマムだが一貫した「レイアウト／建物」が成立する**体験を提供する。各ステップは UI の説明に付随するが、**進捗の単位は常に「建物・空間が増える／仕上がる」こと**とする。

- **NG**: 「構築ボタンを押しましょう」「オービットを試しましょう」だけが並ぶツアー。
- **OK**: 「このステップが終わると敷地の形が決まる」「ここまでで一室の輪郭が閉じる」など、**成果物ベースのマイルストーン**で構成する。

---

## 2. ゴール成果物の定義（完了状態）

チュートリアル完了時、ユーザー本人の操作だけでシーンに以下が揃っていること（**MVP の Definition of Done**）。

| # | 成果物 | 受け入れ条件（例・調整可） |
|---|--------|------------------------------|
| G1 | **敷地（プロパティライン）** | 閉じたポリゴンが 1 つあり、指定サイズレンジ内または規定プリセットと整合 |
| G2 | **建物コンテナ** | 既定の建物／レベルが選択され、作業対象の床レベルが明確 |
| G3 | **構造：閉じた一室の外周** | 壁（またはフェンス等で代替しない基本案では壁）により **床レベル上で一周する閉ループ** が存在 |
| G4 | **床スラブ／水平仕上げ（いずれか）** | 少なくとも一室分の床がスラブ等で示される（製品都合で省略する場合は要件書で明示し代替マイルストーンを定義） |
| G5 | **出入り口または開口の手がかり** | ドア 1 つ、または意図した開口（壁セグメント削除等）のいずれか — **省略時は G6 を必須化** |
| G6 | **スポーン位置** | ウォークスルーで室内に立てる位置が 1 箇所配置されている |
| G7 | **体験の締め** | ウォークスルーで自分が作った一室を歩いて確認できる |

**備考**

- G4〜G5 はツールサポート状況により **「最小構成」** に落とす（例: 壁＋スポーンのみで MVP とする）。落とす場合も **「一室として認識できる閉空間」は維持**する。
- 「見た目が綺麗」より **編集の因果がつながること** を優先する。

## 3. 対象ユーザーと前提

| セグメント | チュートリアル後に期待する状態 |
|------------|--------------------------------|
| 初回ユーザー | **一通りの編集ループ**（敷地 → 構造 → 歩いて確認）が体験済みで、自分のシーンにミニ建物が残る |
| 検証ユーザー | デモとして「このエディタで短時間で何ができるか」が **成果物で説明できる** |
| 再訪ユーザー（将来） | 別プロジェクト（例: 2 階建てミニチュア）を追加コンテンツとして提供する余地 |

## 4. コンセプト名・体験設計

### 4.1 名称イメージ

- **「最初の一室をつくる」**／**Build your first room**（内部コード名: `tutorial-first-room` 等）

### 4.2 形式：単一プロジェクトのビルドアロング

| 要素 | 要件 |
|------|------|
| **一本の物語** | 冒頭でゴールを見せる（完成イメージのシルエットまたは断面イラスト）。終盤で実シーンと照合する。 |
| **マイルストーン駆動** | 各チャプターの完了条件は **シーン状態の検証**（壁本数・閉ループ・ノード種別など）を第一とし、単なるクリック完了は補助にとどめる。 |
| **許容するガイド** | スナップ強調、シルエットガイド（ゴースト）、寸法ヒント — ただし **幾何はユーザー操作で生成**する（完成モデルを丸ごとロードして終わりにしない）。 |
| **中断／再開** | チャプター単位でセーブ。やり直しは「プロジェクト最初から」または「現在チャプターから」。 |

### 4.3 既存機能との関係

- **ウォークスルー**: チュートリアルの **最終章で成果物を体感する手段**。説明目的の単体ツアーではない。
- **ヘルプ／ツールチップ**: あくまで補助。主線はプロジェクト進行。

## 5. コンテンツ構成案（チャプター／マイルストーン）

以下は **ドラフト**。実装時にエディタのツール可否で調整する。

| チャプター | ユーザーの体感 | マイルストーン（成果） |
|------------|----------------|------------------------|
| **0. はじめに** | ゴールの一室イメージと所要時間（目安 8〜15 分） | チュートリアルモード開始 |
| **1. 敷地を決める** | プロパティライン編集で矩形（または規定形） | **G1** 達成 |
| **2. 建物と階を用意する** | サイト／構造フェーズの移動、レベル選択 | **G2** 達成 |
| **3. 壁で一室を囲む** | 壁ツールで 4 辺（または指定セグメント数）を配置し閉じる | **G3** 達成 |
| **4. 床を引く** | スラブ等で室内を埋める | **G4** 達成（省略時は別マイルストーン定義） |
| **5. 出入りをつくる** | ドアまたは開口 | **G5** 達成 |
| **6. 歩いて確かめる** | スポーン配置 → ウォークスルー | **G6〜G7** 達成 |

**コンテンツトーン**

- 各チャプター冒頭は **「ここまでで ○○ が完成します」** で始める。
- 本文は短く。専門語は括弧で一言だけ。

## 6. 機能要件（FR）

### FR-01 開始・終了・再実行

- 初回提案／設定からの再実行／スキップ／完了記録（永続化）は **0.1 版と同様**に提供する。
- 完了の定義は **§2 の Definition of Done を満たすこと** とする（単に最後のモーダルを閉じただけでは完了にしない）。

### FR-02 チュートリアルモード・シーン整合性

- チュートリアル専用フラグ（例: `tutorial.active`, `tutorial.projectId`）を持ち、**検証ロジックがシーングラフを評価**できること。
- **推奨**: 新規シーンまたはチュートリアル用プリセットシーンで開始し、既存の複雑シーンとの競合を避ける。
- チュートリアル中に作成したノードは通常どおりユーザーシーンに残る（除非破棄オプションを明示的に設ける）。

### FR-03 マイルストーン検証（必須）

- 各チャプター終了条件は **シーン状態に対するプログラム検証**を優先する。
  - 例: 「閉じた壁ループ」「プロパティラインポイント数」「スポーンがレベル子である」等。
- 検証失敗時は **リカバリーヒント**（どのツールで何が足りないか）を表示し、無関係な機能説明に逃げない。

### FR-04 UI ガイド（従属）

- スポットライト／ハイライトは **現在のマイルストーン達成に必要な UI だけ**に限定する。
- 「カメラを回してみよう」は **G7 の直前または成果物確認の文脈**に組み込む（単独の説明ステップにしない）。

### FR-05 アクセシビリティ・国際化

- §0.1 版と同等の最低ライン（キーボード、中断確認、`aria-live` 等）。
- すべてのコピーは i18n キー管理。**ゴール志向の文言**（「一室が完成しました」等）をキー設計に反映。

## 7. 非機能要件（NFR）

| ID | 項目 | 要件 |
|----|------|------|
| NFR-01 | 正しさ | マイルストーン検証は **誤検知／すり抜け**が起きにくいようテストする（壁が閉じていないのに次へ等を禁止） |
| NFR-02 | パフォーマンス・安定性 | §0.1 と同様 |
| NFR-03 | 保守性 | チャプター定義はデータ駆動。**検証関数と UI ターゲット**を同一チャプターに束ねる |
| NFR-04 | 拡張 | 第 2 のプロジェクト（例: 屋根付きミニハウス）を追加できない設計にしない |

---

## 8. UI／UX 要件

- **進捗表示**: 「一室プロジェクト」の **全景チェックリスト**（敷地／壁／床／出入り／歩行）を常時または折りたたみで表示し、**機能名ではなく成果名**でラベルする。
- **完成の演出**: 最終マイルストーン達成時に **ビフォーアフター**またはハイライトで一室を強調し、達成感を出す。
- 競合モーダル・クラッシュ時の挙動は §0.1 と同様。

## 9. 技術的検討（実装メモ）

| 項目 | メモ |
|------|------|
| 検証の置き場 | `tutorial/validators.ts` のような層にチャプターごとの `validate(scene): MilestoneResult` を集約 |
| 幾何検証 | 壁グラフの連結・閉ループ判定はコア／ユーティリティ側の再利用を検討（重複実装を避ける） |
| ガイドオーバーレイ | Canvas 外 DOM を主とし、必要なら 2D フロアプラン上にゴーストを描く |
| データ | `tutorial/chapters.ts` に `{ id, titleKey, validate, spotlightTarget, hints }` |

## 10. 成功指標（KPI 案）

| 指標 | 意味 |
|------|------|
| **プロジェクト完了率** | §2 の DoD を満たして終了した割合 |
| **チャプター離脱ポイント** | どの成果物で詰まっているか（検証失敗ログ） |
| **完了までの時間** | 中央値・90 パーセンタイル |
| **完了後のウォークスルー起動率** | G7 に相当する体験まで届いているか |

## 11. リスクと未決事項

| リスク | 対策 |
|--------|------|
| 幾何検証が難しい | MVP は矩形一室に限定し、許容誤差とスナップを強める |
| ツール不足で G4/G5 が無理 | §2 の「最小構成」に落とし、仕様として文章で固定 |
| ユーザーが自由編集で破壊 | チュートリアル中は **Undo スタックの誘導**または「このチャプターをやり直す」でロールバック |

**未決**

- チュートリアルシーンの初期状態（完全空 vs 建物枠のみ vs ガイドポイントのみ）。
- 多言語で寸法表記（m / ft）をどう揃えるか。

## 13. 結論（企画サマリー）

チュートリアルは **「最初の一室をつくる」単一プロジェクト**であり、ユーザーは手を動かし続けることで **敷地から一室・スポーンまでが成果として残る**。機能説明はマイルストーン達成のためにだけ提示する。**完了の定義はシーン上の成果物**とする。
